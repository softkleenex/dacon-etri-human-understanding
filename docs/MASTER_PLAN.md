## 3. 에이전트 및 휴먼-인-더-루프(HITL) 작업 지침 (Operational Guidelines)

장기 실행 모드(Long-running session)에서 컨텍스트 메모리 초과를 방지하고, 기계(Agent)와 사람(User)이 효율적으로 협업하기 위한 규칙입니다.

1. **Human-in-the-Loop (HITL) 피드백 루프**:
   - DACON은 제출 횟수 제한이 엄격하며, API 조회가 어려운 경우가 많습니다.
   - 로컬 OOF 성능이 과거 최고 기록을 돌파할 때만 제출을 고려합니다.
   - 사용자는 실제 리더보드(LB) 점수를 확인한 뒤, 👉 **[제출 및 실험 기록부 (SUBMISSION_HISTORY.md)](SUBMISSION_HISTORY.md)** 에 기록을 남깁니다. 에이전트는 이를 읽고 다음 탐색 전략을 수정합니다.
   - 데이터 분석 중 발견한 특이사항이나 컬럼 정보는 👉 **[데이터 명세서 (DATA_DICTIONARY.md)](DATA_DICTIONARY.md)** 에 기록하여 에이전트가 코딩 전 참조할 수 있도록 합니다.

2. **컨텍스트 절약 (Memory Efficiency)**:
   - 무거운 데이터프레임 출력, 긴 에러 로그 전체 출력을 금지합니다.
   - 부분적이고 외과수술적인(Surgical) 코드 수정을 지향합니다.
   - 반복적인 작업이나 대량의 로그 확인은 `generalist` 등의 서브 에이전트에게 위임하여 메인 세션의 히스토리를 가볍게 유지합니다.

3. **완전한 자율 실행 (Autonomous Execution)**:
   - 주어진 인프라 내에서 코드를 자율적으로 수정, 실행, 디버깅합니다.

4. **작업 분리 보장 (Separation of Concerns)**:
   - 스크립트, 설정 파일, 마크다운 문서 등 성격이 다른 파일들을 명확히 분리하고, `.gitignore`를 통해 대용량 파일이 형상관리에 들어가지 않도록 합니다.
