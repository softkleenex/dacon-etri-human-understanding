# Gemini CLI (AI Agent) 자율 진화 가이드

이 프로젝트의 핵심은 사용자(인간)가 일일이 코드를 타이핑하는 것이 아니라, Gemini CLI라는 **AI 에이전트(컨트롤 타워)**에게 지시를 내리고 코드를 자율적으로 발전시키는 휴먼-인-더-루프(Human-in-the-Loop, HITL) 방식에 있습니다.

---

## 1. 역할 분담 원칙
- **사용자(인간)**: 대회 도메인의 특성을 파악하고, 논문이나 아이디어를 바탕으로 "어떤 방향으로 전진할 것인지(Strategy)" 지시합니다. 또한, 최종적으로 DACON 홈페이지에 결과물을 제출하여 점수(Feedback)를 받아 에이전트에게 알려줍니다.
- **에이전트(Gemini CLI)**: 사용자의 지시를 받아 파일을 읽고(`read_file`), 코드 문맥을 파악한 뒤 외과 수술하듯 코드를 수정(`replace`)합니다. 수정한 코드는 직접 터미널을 통해 실행(`run_shell_command`)하고 에러가 나면 스스로 디버깅합니다.

---

## 2. 자율 루프 모드 (`/ralph:loop`)
에이전트에게 한 번 명령을 내리고 수십 번의 반복 작업(수정 -> 실행 -> 평가)을 자율적으로 수행하게 만들고 싶을 때 사용합니다.

> **💡 프롬프트 예시 (Prompt Example)**
> 
> ```bash
> /ralph:loop "현재 src/features.py에 있는 피처 생성 로직을 개선하려고 해. 날씨 데이터 기반의 이동 평균선(Moving Average)과 지수 평활(EWMA) 피처를 추가해줘.
> 수정 후 `make test`를 실행해보고, 통과하면 `scripts/train.py`를 실행해 로컬 OOF 점수를 확인해.
> 에러가 발생하면 로그를 보고 스스로 코드를 수정해. 만약 OOF 점수가 기존보다 올랐다면 작업을 멈추고 결과를 보고해줘."
> ```

에이전트는 이 명령을 받으면, 목표를 달성할 때까지 코드를 고치고 돌려보는 과정을 스스로 무한 반복합니다.

---

## 3. 서브 에이전트 (Sub-Agents) 활용 전략
에이전트의 '기억(Context)'은 제한되어 있습니다. 터미널 로그를 수천 줄씩 메인 채팅방에 띄우면 뇌 과부하(Token Limit)가 옵니다. 따라서 귀찮고 데이터가 많은 작업은 전문 서브 에이전트에게 위임해야 합니다.

1. **`codebase_investigator`**: "이 버그가 왜 발생한 건지 전체 소스 코드를 뒤져서 아키텍처 관점에서 원인을 찾아줘." (대규모 코드베이스 추적용)
2. **`generalist`**: "방금 학습한 로그 5000줄을 읽고, 어느 에폭(Epoch)부터 Overfitting이 시작되었는지 요약해줘." (단순 무식한 대용량 텍스트 분석용)

---

## 4. 제약 사항 및 안전 수칙 (Safety Protocol)
에이전트는 폭주를 막기 위해 강력한 제약 조건을 가집니다.
1. **원본 데이터 파괴 금지**: `data/raw/` 하위의 파일은 절대 수정하거나 삭제하지 않습니다.
2. **시크릿 유출 방지**: `.env`나 `~/.zshrc`의 토큰, 비밀번호 등을 절대 터미널 로그로 출력하거나 깃(Git)에 커밋하지 않습니다.
3. **행동 전 설명 의무**: 무작정 코드를 지우기 전에, 자신이 왜 이 코드를 수정하는지 사용자에게 1문장으로 보고해야 합니다 (Explain Before Acting).
