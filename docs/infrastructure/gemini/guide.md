# Gemini CLI (AI Agent) 운영 매뉴얼

이 프로젝트의 핵심은 개발자(인간)가 일일이 코드를 타이핑하는 것이 아니라, Gemini CLI라는 **AI 에이전트(컨트롤 타워)**에게 목표를 지시하고 코드를 자율적으로 진화시키는 "휴먼-인-더-루프(Human-in-the-Loop, HITL)" 방식에 있습니다.

## 🎯 사용 목적 (Why use this?)
- **사고의 추상화**: "어떻게 코딩할지" 고민하는 대신 "어떤 가설을 검증할지" 전략에만 집중합니다. 인간은 논문 아이디어를 제시하고, 코드 구현과 디버깅은 에이전트가 알아서 수행합니다.
- **무한 실험 반복**: 점수가 오를 때까지 파라미터를 깎고 피처를 뺐다 넣었다 하는 지루한 노가다를 에이전트에게 위임합니다.

## 🚀 사용 방법 (How to use?)

### 1. 지시 원칙 (HITL)
에이전트에게 일을 시킬 때는 명확한 "초기 조건", "행동 지침", "종료 조건(목표)"을 제시해야 합니다.

> **💡 권장 프롬프트 예시**
> "현재 로컬 K-Fold OOF 점수가 0.82에서 정체되었어. `src/features.py`에 날씨 데이터를 결합한 롤링 윈도우 피처를 5개 추가하고 `make test`로 에러가 없는지 검증해줘. 에러가 없으면 모델을 학습시키고, 점수가 0.83을 넘으면 멈추고 결과를 보고해."

### 2. 자율 루프 모드 (`/ralph:loop`)
에이전트가 질문을 멈추고 혼자서 끝까지 코드를 깎으며 며칠이고 돌아가게 만들고 싶을 때 명령어 앞에 `/ralph:loop`를 붙여 실행합니다. 에이전트는 로그를 보고 스스로 에러를 디버깅하며 전진합니다.

### 3. 서브 에이전트 (Sub-Agents) 활용
Gemini CLI는 여러 인격을 가집니다. 컨텍스트가 터지는 것을 막기 위해 노가다 작업은 전용 에이전트를 호출하여 위임하세요.
- **`codebase_investigator`**: "이 버그가 왜 났는지 `src/` 전체를 뒤져서 아키텍처 관점에서 찾아줘."
- **`generalist`**: "방금 돌아간 Kaggle 훈련 로그 5,000줄 읽고 오버피팅 발생 지점만 요약해줘."

## ⚠️ 실전 주의 사항
에이전트는 폭주를 막기 위해 "원본 데이터(`data/raw`) 파괴 금지", "시크릿 토큰 평문 출력 금지", "파일 전체 덮어쓰기 대신 외과수술적(`replace` 도구) 수정 선호" 등의 안전 수칙을 시스템 레벨에서 부여받았습니다. 에이전트가 코드를 바꾸기 전에는 반드시 "왜 바꾸는지" 1문장으로 설명해야 합니다.
